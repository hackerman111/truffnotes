# .inknote schema 1

The archive is a ZIP stream with UTF-8 entry names. Core values use `CoreCodec` CBOR with defaults encoded. This implementation exports one complete document and does not rewrite SQLite files. Compression and ZIP timestamps are deterministic on the same JVM; the portable identity is the manifest entry hashes, not the compressed container bytes.

Entry order is `document.cbor`, `records/00000000.cbor` through the final record, reachable `assets/<sha256-of-asset-id-UTF8>` in ascending asset ID order, then `manifest.cbor`. ZIP timestamps are zero. Records are complete `SceneObject` values, ordered by ascending object ID. One record is bounded by 8 MiB; a larger record is rejected, never truncated. The header contains the exact `DocVersion`, document kind, complete ordered page and layer descriptors, object count, sorted unique asset IDs and `NativePurpose` (`Document`, `ObjectBundle`, `Collection`, or `Template`; absent means `Document`). Page metadata carries bookmarks, templates and PDF backgrounds. Payload encoding preserves every core editable type, ID and style.

Assets contain their original bytes. Their path encodes the hash of the asset ID to avoid filesystem path injection; the manifest SHA-256 hashes their content. Only assets reachable through core payload references or page template/PDF metadata are admitted. The final manifest contains schema version 1, original document ID, applied revision and a lexicographically sorted list of every preceding entry's path, expanded size and lowercase content SHA-256. It excludes itself.

Import does not extract ZIP names to filesystem paths. Absolute/traversing/duplicate/directory/unknown names, invalid CBOR, noncanonical record sequence, repeated object IDs, unsupported schema, wrong payload digest, nonexistent layer/page ownership, missing/unreachable assets, incorrect manifest hashes or sizes, cancellation and expanded quotas fail the transaction. The defaults are 2 GiB total expanded input including manifest, 200,000 payload entries, 8 MiB per metadata/record and 16 MiB manifest. Assets stream through a 32 KiB buffer. Callers may lower quotas. ZIP input CRC errors abort. The reader buffers one record and a bounded manifest directory, and delegates staged asset bytes to `ImportSink`.

`ImportSink` receives untrusted staged data. `commit` is the sole publication point and must validate the assembled core graph, atomically publish a new document and assets, and reject ID collisions. Failure or cancellation calls `abort`, including failures during commit. A matching library generation may be opened after comparing all canonical entry hashes. A changed generation with the same ID requires an explicit import-as-copy operation that remaps document, space, page, layer, object and internal link references together; this codec does not silently perform that remap. The runtime must also ensure the newly chosen copy ID does not exist.

`SnapshotReader` is a frozen revision lease shared by Durable and Recovery export; the encoder is identical for both. Its record stream must enumerate the entire frozen directory and its asset resolver must include pending staged assets. It must remain valid across editing/GC until closed. `ResidentSnapshotReader` is a small-document adapter, requires an externally held pin, and rejects a nonresident directory. It does not provide a disk-backed bounded snapshot implementation. Recovery export does not flush or advance any saved watermark.

`SafeExport` accepts a newly created output, or an output advertising a proven provider-specific atomic replacement transaction. Nonatomic overwrite is rejected before opening. Completion occurs only after encoder finish, flush and stream close. I/O exceptions and cancellation abort the new output; output implementations must clean incomplete files. `AndroidExchangeOutput` is only for a fresh `ACTION_CREATE_DOCUMENT` result. Providers that silently discard bytes while returning success cannot be detected by `OutputStream`; a provider-specific verification receipt is required to prove that behavior.

## Editable selection and reusable bundles

`NativeSelection.project(snapshot, scope, layerIds, visibleLayersOnly)` returns a validated editable snapshot and a report before any bytes are written. Supported scopes are the full document, explicit page IDs, a zero-based inclusive page range, one page/region, and explicit object IDs. Selected pages retain their source order. Selected layers preserve original descriptors. Layer filters are explicit; visible-only excludes hidden layers and does not mutate the source.

Native region scope means complete editable objects intersecting the requested rectangle in original document coordinates. It does not destructively clip object geometry, crop page backgrounds, or delete information outside the rectangle. Group parents/members, connector endpoints and Sticky attachments form a dependency closure. Dependencies outside selected layers fail rather than leaking excluded-layer data. `SelectionReport.dependencyObjects` identifies whole objects added by closure. `report.region` records the requested rectangle for preview; callers must show this policy before writing. Use image export for a pixel-clipped region. Tape content remains editable and is never redacted by native export.

Internal links targeting omitted pages are detached, with their title/URL retained. Their object IDs appear in `SelectionReport.detachedLinks`. The report is returned to the caller, not silently treated as a lossless full-document copy. The report itself is not encoded as document content.

`NativeBundles.write` uses the same `.inknote` encoder, header, payload records and assets for all purposes. `ObjectBundle` requires an explicit object scope. `Collection` can describe a selected reusable collection of objects. `Template` defaults to the first source page and requires exactly one resulting page; an explicit page scope selects another page, including a page with a PDF background reference. A multi-page PDF template therefore retains its complete source asset but selects one editable page reference. The UI must preview that page selection. Bundles preserve source revision/IDs and are imported through `NativeArchive.read`; changed source-ID collisions require explicit import-as-copy remapping. The purpose field does not grant overwrite permission.

## Multi-document collection envelope

`NativeCollection.write(items, output)` writes standalone nested `.inknote` streams without buffering a whole nested archive. Items are sorted by their unique logical library path; original document IDs must also be unique. ZIP entry paths are fixed `documents/00000000.inknote`, etc., followed by `collection.cbor`. Logical library paths are metadata only and preserve folder hierarchy. Empty, absolute, dot/traversing, backslash, control-character and colon-bearing paths are rejected.

`CollectionManifest` schema 1 contains ordered logical path, nested entry name, document ID, exact nested ZIP byte length and SHA-256. Both the nested payload manifests and envelope byte digests are verified. Expanded-payload quota is shared across all documents, with a separate same-sized cap on aggregate nested ZIP bytes. The collection manifest is bounded by the regular manifest quota and remaining expanded budget. Entry count is bounded; nested readers retain their ordinary per-record quotas.

`NativeCollection.read` invokes `NativeCollectionSink.document(index)` for private child staging. A child's `ImportSink.commit` only seals staging; it must not publish a document. After every child and envelope hash/path/schema check succeeds, the collection sink's final `commit(manifest)` may publish atomically and preserve logical hierarchy. Any failure/cancellation calls every staged child's `abort` and the collection `abort`, even for children whose own manifest already passed. Filesystem/library publication and rollback across multiple documents are the collection sink's responsibility; a direct publishing single-document sink cannot be reused here.


Collection documents may include an optional `names` array, one display name per `libraryPath` component. Paths remain unique safe logical identifiers; display names may contain separators or repeat. Readers without this array use the path components as names. The Android importer remaps all document/folder IDs and publishes the hierarchy atomically only after every child/archive hash is validated.
