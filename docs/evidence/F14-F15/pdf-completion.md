# F14 PDF implementation and measured boundary

2026-11-07. Changes are uncommitted on `fix/editor-through-f15`.

## Implementation

`PdfCompositionWriter` uses `com.tom-roush:pdfbox-android:2.0.27.0` for writing/composition; PDFium remains the existing isolated reader/renderer. The upstream Android port documents its Apache-2.0 license, Android API 19+ support, Maven Central coordinates and resource-loader initialization: <https://github.com/TomRoush/PdfBox-Android>. The selected port is based on PDFBox 2.0.27. This is a new dependency, not an assertion that the existing PDFium binding can write PDFs.

Source PDF pages and templates are imported as PDF forms. Paths, text and resources survive; a whole source page is not converted to a bitmap. CropBox offsets/rotation are normalized using the imported form matrix. Embedded PDF objects use their complete affine placement and effective layer/object opacity. Source forms and ordinary object replay batches are emitted in document layer/z order. Existing imported PDFs use a locked PdfObject background layer; the import planner does not simultaneously create a metadata PDF background.

VectorPdf and FlattenedPdf both compose source forms plus shared Android Canvas overlays. FlattenedPdf merges annotation appearances into page content. Source annotation appearances are merged before importing their source page. Link annotations remain navigable in flattened output; they carry no editable ink appearance. StandardAnnotations writes genuine `/Ink`, `/Text`, `/Square` and `/Circle` dictionaries with `/AP` appearance streams generated by the same CanvasReplay, GeometryPort and TextPort used by other export targets. InkList coordinates are in output page coordinates. Annotation rectangles bound their replay region. Unsupported editable annotation types use a shared appearance and enter the export report. Connectors now consume shared ShapeReplayGeometry in CanvasReplay rather than disappearing or using a PDF-only brush.

PdfOverlay accepts explicit object IDs for direct scene lookup and an includePaper switch. Ordinary vector/flattened objects are batched between embedded PDF objects; standard annotations replay their own bounded rectangles. Export does not rebuild the complete snapshot for each object. Android Canvas PDF replay does not allocate software raster previews. Grid paper consumes the existing shared grid samples once per page. PDFBox scratch storage is memory-only with a 64 MiB limit; cumulative opened source files are admitted up to 128 MiB. No internal temporary output PDF is required. These admission limits can fail a large export; they are not a measured Android RSS guarantee.

Source URI links, named/direct GoTo page links and outlines are remapped to exported pages, including affine-transformed embedded source placements. Missing page targets and unsupported actions are reported. Notebook LinkAnchor objects emit actual links. Android feature export returns the report to the caller. It freezes layer selection/visibility, Sticky expansion and Tape reveal in an export-only snapshot. Selection/object export uses NativeSelection dependency closure and a union crop. PNG/JPEG use their streaming encoders; JPEG now uses the shared eight-row StreamingJpeg writer supplied by the parent task.

## Precise remaining acceptance and fallback boundary

The two-viewer gate is demonstrated for the composition backend and host-generated fixtures. It has not been demonstrated for PDFs exported by Android PdfDocument on a physical device/emulator. Device verification of real handwriting pressure, Android font embedding/substitution, image resources, layer opacity, Sticky/Tape policy combinations and actual SAF providers remains open. Host renderer regressions and Android compilation do not prove those cases.

Only the listed annotation families are editable standard objects. Other app objects remain appearance content and are listed when StandardAnnotations is requested. Text fallback reports explicitly name Android shaping/font embedding or substitution. Non-solid Tape reports its shared texture appearance. Source annotation editing is not preserved; source appearance is merged and that limitation is reported. A source annotation whose appearance cannot be constructed is reported as unsupported. Rich media, custom JavaScript/Launch actions, XFA, PDF portfolios, embedded-file actions and other non-GoTo/non-URI actions are not preserved. Original page destinations become page-fit destinations; exact original zoom/XYZ coordinates are not retained. If a source page is exported more than once, page-navigation mapping selects the first mapped copy. Region exports omit source navigation mapping because original target coordinate mapping is unavailable. These are explicit fallbacks, not silent proof of full PDF equivalence.

This report covers the PDF-owned implementation. It does not close the overall F14/F15 device, recovery or publication gates owned by the parent task.
