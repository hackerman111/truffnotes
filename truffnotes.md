# Техническое задание

## Inkspace — рукописный редактор для Android-планшетов

**Версия:** 1.1  
**Платформа:** исключительно Android  
**Устройства:** планшеты со стилусом или сенсорным экраном  
**Основной интерфейс:** Goodnotes-style Notebook UI  
**Дополнительный интерфейс:** Canvas Studio  
**Основной формат документов:** редактируемая векторная заметка  
**Хранение:** локальное, с поддержкой системного файлового менеджера Android

---

# 1. Назначение приложения

Inkspace — Android-приложение для создания и организации рукописных заметок на планшете.

Приложение объединяет возможности Goodnotes, Notewise, Notability, MyScript Notes, Concepts, Flexcil, Noteful и Xournal++.

Основные направления:

1. Рукописный ввод и редактирование векторных штрихов.
2. Создание и управление электронными тетрадями.
3. Работа с бесконечным холстом.
4. Геометрическое распознавание фигур.
5. Управление содержимым через жесты стилуса.
6. Чтение и аннотирование PDF.
7. Управление страницами, слоями и изображениями.
8. Локальное хранение и администрирование файлов.
9. Работа с несколькими документами на одном экране.

Приложение ориентировано прежде всего на использование стилуса.

## 1.1. Принципы

- Пользователь должен иметь возможность начать писать сразу после открытия заметки.
- Основные инструменты должны быть доступны одним нажатием.
- Все созданные рукописные штрихи должны оставаться редактируемыми.
- Интерфейс должен быть оптимизирован для пальцев и стилуса.
- Работа с заметками не должна требовать регистрации.
- Все основные функции должны работать без интернета.
- Файлы должны быть переносимыми между устройствами.
- Нельзя терять исходные данные при смене режима отображения.
- Основные действия должны поддерживать Undo/Redo.
- Панели должны скрываться, освобождая место для холста.

## 1.2. Исключённые функции

В текущей версии не разрабатываются:

- Генеративный ИИ.
- OCR рукописного текста.
- Преобразование рукописи в печатный текст.
- Преобразование формул в LaTeX.
- Распознавание математических выражений.
- Автоматическое решение задач.
- Нейросетевое улучшение почерка.
- AI-поиск и генерация конспектов.

Геометрическое распознавание окружностей, прямых, прямоугольников и других фигур остаётся.

# 2. Режимы интерфейса

Приложение должно иметь два независимых режима пользовательского интерфейса.

## 2.1. Goodnotes-style UI — основной

**Статус: основной режим, включён по умолчанию.**

Интерфейс должен использовать привычную для Goodnotes организацию работы с тетрадями: библиотека с папками и обложками, вкладки документов, верхние панели навигации и инструментов, страницы бумаги, боковая панель миниатюр.

Этот режим предназначен для большинства пользователей.

Он должен быть полностью функционален уже в первой версии.

Основные характеристики:

- Постраничный редактор.
- Бумажные шаблоны.
- Панель инструментов в верхней части экрана.
- Вкладки документов.
- Библиотека папок и тетрадей.
- Миниатюры страниц.
- Закладки и оглавление.
- Быстрое переключение пера, маркера и ластика.
- Увеличенное окно письма.
- Режим чтения.
- Полноэкранный режим.
- Аннотирование PDF.

## 2.2. Canvas Studio — дополнительный

**Статус: дополнительный режим, вторичный на первом этапе.**

Canvas Studio предназначен для пользователей, которым необходимы бесконечный холст, сложные схемы, несколько рабочих областей и расширенное управление объектами.

Отличия от основного режима:

- Холст может не иметь границ.
- Панели могут свободно перемещаться.
- Доступна пространственная мини-карта.
- Страницы можно размещать как отдельные области Frame.
- Больше инструментов управления объектами.
- Расширенные средства выравнивания и работы со слоями.
- Несколько областей документа можно отображать одновременно.

## 2.3. Переключение режимов

В меню документа должна присутствовать команда:

**Interface Mode → Notebook / Canvas Studio**

Также режим можно выбрать в настройках приложения.

Требования:

- При переключении не изменяются сохранённые штрихи.
- Не создаётся копия документа.
- Не теряются слои и изображения.
- Сохраняется возможность Undo/Redo.
- Сохраняются координаты объектов.
- Пользователь может вернуться к предыдущему режиму.
- Последний выбранный интерфейс запоминается для документа.

**Режим интерфейса и тип документа должны быть независимыми понятиями.**

Например, обычную тетрадь можно открыть через Canvas Studio, а документ с несколькими Frame — через постраничное представление, если это допустимо его структурой.

При наличии объектов за пределами страниц редактор не должен удалять их при переключении в Notebook UI.

# 3. Основной интерфейс Goodnotes-style UI

## 3.1. Общая организация

Основной интерфейс должен состоять из следующих компонентов:

1. Главная библиотека.
2. Панель открытых документов.
3. Панель навигации документа.
4. Панель инструментов письма.
5. Рабочая область страниц.
6. Выдвижная панель страниц.
7. Контекстные меню.
8. Настройки выбранного инструмента.

По расположению и логике интерфейс должен быть близок к Goodnotes, сохраняя собственное визуальное оформление Inkspace.

Требуется воспроизвести удобство использования, но не копировать чужие логотипы, иконки и другие охраняемые элементы оформления.

## 3.2. Главная библиотека

После первого запуска открывается библиотека заметок.

По умолчанию отображается раздел Documents.

### Элементы экрана

**Верхняя область:**

- Название библиотеки.
- Поиск.
- Кнопка создания.
- Переключение отображения Grid/List.
- Режим массового выделения.
- Настройки.

**Основная область:**

- Папки.
- Тетради.
- PDF-файлы.
- Другие поддерживаемые документы.

**Разделы библиотеки:**

- Documents.
- Favorites.
- Recent.
- Templates.
- Trash.

В отличие от облачных приложений, раздел Shared не нужен в первой версии.

### Отображение Grid

Каждая заметка показывается плиткой.

Плитка содержит:

- Обложку.
- Название.
- Дату последнего изменения.
- Значок типа файла.
- При необходимости индикатор избранного.

Для папки отображаются название, значок и при желании миниатюры содержащихся заметок.

### Отображение List

Компактный список содержит название, тип, дату изменения и дополнительную информацию.

Пользователь может менять размер элементов списка и сетки.

### Создание документа

Кнопка `+ New` открывает меню:

- Notebook.
- Infinite Canvas.
- Folder.
- Import PDF.
- Import Image.
- From Template.

**Notebook должен быть первым и основным действием.**

## 3.3. Создание тетради

После выбора Notebook открывается экран создания.

Пользователь задаёт:

- Название тетради.
- Обложку.
- Цвет бумаги.
- Размер страниц.
- Ориентацию.
- Шаблон страницы.
- Вертикальное или горизонтальное перелистывание.

Встроенные форматы:

- A4.
- A5.
- Letter.
- Пользовательский размер.

Встроенные шаблоны:

- Чистый лист.
- Линейка.
- Клетка.
- Точки.
- Миллиметровая сетка.
- Cornell.
- Пользовательский шаблон.

Последние использованные настройки предлагаются для новой тетради.

После нажатия Create пользователь сразу попадает в редактор с активным инструментом Pen.

## 3.4. Панель вкладок

В верхней части редактора располагается панель вкладок открытых документов.

Каждая вкладка содержит:

- Название.
- Индикатор типа документа при необходимости.
- Кнопку закрытия либо контекстное меню.

Поддерживаются:

- Открытие нескольких заметок.
- Переключение одним нажатием.
- Закрытие.
- Восстановление недавно закрытого документа.
- Изменение порядка вкладок перетаскиванием.
- Прокрутка полосы вкладок, если они не помещаются.
- Сохранение открытых вкладок после перезапуска.

На небольших экранах вкладки могут сворачиваться в компактный список.

## 3.5. Панель навигации документа

Под вкладками располагается основная панель навигации.

**Левая часть:**

- Возврат к библиотеке.
- Открытие боковой панели.
- Поиск.
- Переключение Edit/Read Only.

**Центр:**

- Название документа.
- Панель инструментов или её основная часть.

**Правая часть:**

- Добавление страницы.
- Закладка.
- Share/Export.
- Дополнительное меню.

Состав элементов адаптируется к размеру экрана.

В портретном режиме второстепенные действия могут перемещаться в меню More.

## 3.6. Панель инструментов письма

Основная панель должна содержать:

1. Undo.
2. Redo.
3. Pen.
4. Highlighter.
5. Eraser.
6. Lasso.
7. Shape.
8. Elements.
9. Image.
10. Text.
11. Laser Pointer.
12. Дополнительные инструменты.

На широком экране кнопки располагаются в одной горизонтальной панели.

На узком экране часть инструментов может сворачиваться в раскрываемое меню.

### Поведение инструментов

**Одиночное нажатие:**

Выбрать инструмент.

**Повторное нажатие на активный инструмент:**

Открыть настройки или быстрые пресеты.

**Долгое удержание:**

Открыть подробные настройки инструмента.

**Перетаскивание в режиме настройки:**

Изменить порядок инструментов.

Выбранный инструмент должен иметь отчётливое состояние активности.

## 3.7. Панель параметров активного инструмента

При выборе пера показываются быстрые параметры:

- Цвет.
- Толщина.
- Стиль.
- Сохранённые пресеты.

При выборе маркера:

- Цвет.
- Толщина.
- Прозрачность.

При выборе ластика:

- Размер.
- Segment Eraser.
- Stroke Eraser.
- Object Eraser.

При выборе фигур:

- Цвет контура.
- Толщина.
- Заливка.
- Привязка.

Панель параметров должна иметь компактный режим. Если настройки не используются, её можно скрыть, оставив только выбранный пресет.
Панель также должна быть подвижной:
Сверху: горизонтальная панель под вкладками, основной вариант интерфейса Goodnotes-style.
Снизу: горизонтальная панель над системной областью навигации Android.
Перемещение: долгое удержание специального маркера панели и перетаскивание к выбранному краю. Во время движения показывается предпросмотр закрепления.
Настройка: альтернативный способ через Settings → Interface → Toolbar Position.
Оформление: настраиваемые размеры кнопок, порядок инструментов, пресеты, компактный режим.
Адаптация: отдельное сохранение положения для портретной и альбомной ориентации, корректная работа в Split View.
Холст: при закреплённой панели доступная область холста пересчитывается, чтобы панель не перекрывала страницу.
Focus Mode: пользователь может оставить панель у выбранного края, автоматически скрывать её или использовать плавающий вариант.

## 3.8. Рабочая область

Основную часть экрана занимает бумажная страница.

По умолчанию:

- Страница центрируется по ширине.
- Фон вокруг страницы нейтральный.
- Между страницами есть небольшой визуальный отступ.
- Страницы прокручиваются вертикально.
- Масштаб сохраняется для документа.
- Рукописный ввод доступен сразу после открытия.

Допускается включать горизонтальное перелистывание страниц.

При приближении страницы пользователь может прокручивать её пальцем.

Поворот холста необязателен для основного режима и по умолчанию может быть отключён, чтобы исключить случайные повороты при письме.

## 3.9. Боковая панель страниц

Кнопка Sidebar открывает выдвижную панель.

В ней находятся вкладки:

- Pages.
- Outline.
- Bookmarks.
- Layers.

### Pages

Отображаются миниатюры страниц.

Действия:

- Переход к странице.
- Добавление.
- Дублирование.
- Удаление.
- Перемещение.
- Поворот.
- Массовое выделение.
- Экспорт.
- Перенос страниц в другую заметку.

Изменение порядка выполняется долгим удержанием и перетаскиванием миниатюры.

### Outline

Иерархическое оглавление документа.

Пользователь может:

- Создавать разделы.
- Переименовывать.
- Менять порядок.
- Создавать подразделы.
- Привязывать раздел к странице.

### Bookmarks

Список страниц, отмеченных пользователем.

Нажатие открывает соответствующую страницу.

### Layers

Список слоёв текущей страницы или документа.

Панель позволяет переключать активный слой, менять порядок, скрывать и блокировать слои.

## 3.10. Режим Read Only

Переключение Edit/Read Only должно быть доступно из верхней панели.

В Read Only:

- Рисование отключено.
- Случайные касания не меняют документ.
- Стилус и палец используются для навигации.
- Работают закладки и ссылки.
- Работают поиск и оглавление.
- Доступно копирование текста PDF.
- Можно просматривать слои, если это разрешено настройками.

Выход из Read Only возвращает предыдущий инструмент.

## 3.11. Полноэкранный режим

Кнопка Focus скрывает:

- Вкладки.
- Панель навигации.
- Боковые панели.
- Дополнительные индикаторы.

Плавающая панель инструментов остаётся доступной.

Пользователь может настроить её положение:

- Сверху.
- Снизу.
- Слева.
- Справа.
- В свободной позиции.

Переход в полноэкранный режим не должен менять масштаб или положение страницы.

## 3.12. Портретная и альбомная ориентация

### Альбомная

- Вкладки располагаются сверху.
- Панель инструментов горизонтальная.
- Боковая панель может быть закреплена.
- Страница центрируется в оставшейся области.

### Портретная

- Интерфейс становится компактнее.
- Второстепенные кнопки скрываются в меню.
- Боковая панель открывается поверх холста.
- Инструменты могут размещаться снизу для доступа большим пальцем.
- Вкладки могут быть представлены раскрываемым списком.

При изменении ориентации приложение должно сохранять текущий документ, положение просмотра, выбранный инструмент и выделение, если оно может быть корректно восстановлено.

# 4. Поддержка Android

## 4.1. Платформа

Приложение разрабатывается только для Android.

Версии для iPadOS, iOS, Windows, macOS и Linux в рамках этого ТЗ не предусматриваются.

Рекомендуемая исходная целевая поддержка — Android 10 и новее, с последующей проверкой совместимости конкретных устройств.

Минимальную версию Android допускается скорректировать после выбора графического движка и измерений производительности.

## 4.2. Типы устройств

Необходимо поддерживать Android-планшеты разных производителей.

Приоритетные категории тестирования:

- Samsung Galaxy Tab с S Pen.
- Планшеты Lenovo со стилусом.
- Планшеты Xiaomi с совместимым стилусом.
- Планшеты Huawei с Android-совместимой средой, где доступны необходимые системные интерфейсы.
- Планшеты с универсальным ёмкостным стилусом.
- Планшеты без стилуса, с рисованием пальцем.

Нельзя строить основной редактор исключительно на проприетарных API Samsung.

Специфичные функции S Pen допустимо использовать как дополнение к стандартному Android API.

## 4.3. Работа со стилусом

Обрабатывать Android MotionEvent:

- ACTION_DOWN.
- ACTION_MOVE.
- ACTION_UP.
- ACTION_CANCEL.
- ACTION_POINTER_DOWN.
- ACTION_POINTER_UP.
- События наведения при поддержке.

Учитывать:

- Pointer ID.
- Тип инструмента.
- Координаты.
- Давление.
- Наклон.
- Ориентацию.
- Доступные аппаратные кнопки.
- Исторические точки движения.

Для повышения точности линии необходимо использовать исторические точки MotionEvent, а не только последнюю координату события.

## 4.4. Palm Rejection

При касании ладони система может отправить отмену события.

Приложение должно поддерживать ACTION_CANCEL и FLAG_CANCELED на совместимых версиях Android.

Отменённое касание не должно оставлять на холсте случайную линию.

Нужен режим «рисование только стилусом», если устройство позволяет различать аппаратное перо и касания пальцев.

## 4.5. Работа в фоне

Приложение должно корректно обрабатывать:

- Сворачивание.
- Блокировку экрана.
- Смену ориентации.
- Переключение между приложениями.
- Недостаток памяти.
- Принудительное завершение системой.
- Возврат после длительного отсутствия.

Автосохранение не должно зависеть от того, остаётся ли приложение постоянно активным.

## 4.6. Многооконность Android

На совместимых планшетах должны поддерживаться:

- Split Screen.
- Изменение размеров окна.
- Работа рядом с PDF-просмотрщиком.
- Перетаскивание поддерживаемого содержимого из других приложений.
- Корректное перестроение интерфейса при уменьшении рабочей области.

Внутренний Split View приложения разрабатывается независимо от системной многооконности.

## 4.7. Системная интеграция

Обязательны:

- Android Sharesheet.
- Системный выбор файлов.
- Импорт PDF из других приложений.
- Приём файлов через «Открыть с помощью».
- Экспорт в выбранную пользователем папку.

Приложение не должно запрашивать доступ ко всему хранилищу без необходимости.

# 7. Ластик

Обязательные режимы:

**Segment Eraser:** удаление пересечённого участка штриха.

**Stroke Eraser:** удаление штриха целиком.

**Object Eraser:** удаление целых объектов.

Дополнительные настройки:

- Размер.
- Форма области стирания.
- Только активный слой.
- Все видимые незаблокированные слои.
- Временная активация кнопкой стилуса.

## 7.1. Scribble to Erase

Быстрое зигзагообразное зачёркивание может распознаваться как команда удаления.

Требования:

- Жест работает без переключения инструмента.
- Обычные штрихи не должны ошибочно удаляться.
- Распознавание можно отключить.
- Ошибочное удаление отменяется одним Undo.

# 18. Хранение Android

## 18.1. Local-first

Пользователь должен иметь возможность пользоваться приложением без аккаунта.

Все документы сохраняются локально.

## 18.2. Формат

Предлагаемый формат: `.inknote`.

Он содержит:

- Метаданные.
- Страницы.
- Слои.
- Штрихи.
- Фигуры.
- Текстовые блоки.
- Изображения.
- Вложения.
- Ссылки.
- Закладки.
- Версию схемы.

Формат должен поддерживать перенос между Android-устройствами.

## 18.3. Android Storage Access Framework

Для доступа к файлам использовать штатные механизмы Android:

- ACTION_OPEN_DOCUMENT.
- ACTION_CREATE_DOCUMENT.
- ACTION_OPEN_DOCUMENT_TREE.
- Document URI.
- Длительные разрешения доступа, когда они поддерживаются.

Приложение должно учитывать ограничения Android 11+ на выбор отдельных системных каталогов.

Нельзя предполагать, что произвольный физический путь доступен для чтения или записи.

## 18.4. Организация хранения

По умолчанию библиотека находится во внутреннем хранилище приложения либо в выбранном пользователем расположении, доступном через системный провайдер документов.

В настройках доступны:

- Экспорт всей библиотеки.
- Выбор внешней папки для документов, если Android предоставляет доступ.
- Импорт существующей библиотеки.
- Создание резервной копии.
- Восстановление из копии.

Документы не должны быть привязаны к единственной внутренней базе, из которой невозможно получить самостоятельные файлы.

## 18.5. Автосохранение

- Сохранение изменений без блокирования письма.
- Журнал незавершённых операций.
- Защита от частичной записи.
- Восстановление после аварийного завершения.
- Проверка целостности.
- Обнаружение конфликтующих изменений.

## 18.6. Корзина

Удалённые файлы попадают в корзину приложения.

Поддерживаются:

- Восстановление.
- Окончательное удаление.
- Очистка корзины.
- Настройка срока хранения.

# 24. Требования к первой рабочей версии

Основной пользовательский сценарий:

1. Пользователь запускает Inkspace на Android-планшете.
2. Открывает библиотеку с папками и обложками.
3. Создаёт Notebook.
4. Выбирает бумагу и обложку.
5. Начинает писать стилусом.
6. Меняет инструменты через верхнюю панель.
7. Рисует геометрические фигуры с удержанием.
8. Выделяет и перемещает рукопись через лассо.
9. Добавляет страницы.
10. Открывает боковую панель и меняет порядок страниц.
11. Импортирует PDF и пишет поверх него.
12. Возвращается в библиотеку.
13. Перемещает тетрадь в папку.
14. Экспортирует документ.
15. После перезапуска продолжает редактирование без потери данных.

**Goodnotes-style UI должен оставаться полноценным основным интерфейсом приложения, а не временным демонстрационным экраном.** Расширение Canvas Studio не должно требовать замены архитектуры рукописного редактора или формата хранения.
